## 卷一 · 周二：systemd 服务管理（100 分 + 加分）

### 一、概念快问（每题 8 分，共 40 分）

**1.** 判断对错，并各用一句话说明理由
- ① `systemctl start nginx` 和 `systemctl enable nginx` 效果一样。
- ② 改完 `/etc/systemd/system/xxx.service`，只要 `systemctl restart xxx` 就一定生效。

**2.** 想知道 nginx 现在**是不是活着**、**是不是开机自启**，分别用哪两条命令？

**3. 填空**：服务手动启动能跑，但**重启电脑后没了**，说明少了 ______ 这一步。（填一个命令）

**4. 填空**：`systemctl status` 输出里两行最关键：
- `Loaded:` 这一行告诉你 ______
- `Active:` 这一行告诉你 ______

**5.** 服务启动失败了，要看"到底为什么失败"，写出**最先敲的两条**命令。

### 二、.service 文件（每题 12 分，共 36 分）

**6.** 写出 `.service` 文件的**三个核心段**名称（方括号形式）。

**7. 补全下面这个服务文件**（填 ①②③④）：

```ini
[Unit]
Description=我的巡检脚本
After=network.target

[Service]
Type=simple
① =/opt/scripts/check.sh      # 这个服务到底要跑什么
Restart=②                      # 程序挂了自动拉起来

[Install]
③ =multi-user.target

# 改完这个文件，必须执行 ④ 让 systemd 重新读取
```

**8.** 用**大白话**（各一句话）解释 `ExecStart` 和 `WantedBy` 分别是干什么的。

### 三、情景排错（每题 12 分，共 24 分）

**9.** 写了个 `check.service`，敲 `systemctl start check` **终端一点报错都没有**，但 `systemctl status check` 显示 `Active: failed (Result: exit-code)`。
问：接下来敲哪条命令看具体原因？这条命令大概会告诉你什么？

**10.** 手动启动成功、`status` 正常，重启虚拟机之后服务消失了。
问：**原因是什么**？**怎么修**（写出命令）？

### 加分题

把虚拟机上一个小脚本（比如 `date >> /tmp/test.log`）写成 systemd 服务，`enable` + `start`，截图 `systemctl status`。

<details>
<summary>答案与解析（做完再点开）</summary>

**1.** ① 错。`start` 是**现在**启动，`enable` 是**开机时**自动启动，两件事。
② 错。改完服务文件必须先 `systemctl daemon-reload`，否则 systemd 内存里仍是旧配置，`restart` 不会重读文件。

**2.** `systemctl status nginx`（活没活）、`systemctl is-enabled nginx`（开不自启）。
注：`status` 的 `Loaded:` 行其实也直接写了 enabled/disabled，看一眼就行。

**3.** `systemctl enable xxx`

**4.** `Loaded:` = 服务文件在**哪个路径** + 是否开机自启（enabled/disabled）；
`Active:` = 当前**运行状态**（active(running) / failed / inactive）。

**5.** `systemctl status 服务名`（看现象）→ `journalctl -u 服务名 -e`（看原因）。

**6.** `[Unit]` `[Service]` `[Install]`（首字母大写，Linux 区分大小写）。

**7.** ① `ExecStart`　② `on-failure`　③ `WantedBy`　④ `systemctl daemon-reload`

**8.** `ExecStart` = 这个服务启动时要执行哪条命令/程序；
`WantedBy` = 它挂在哪个启动级别（target）上，`enable` 时会在 `/etc/systemd/system/multi-user.target.wants/` 里建软链接。
口诀：**ExecStart 决定跑什么，WantedBy 决定跟谁一起跑。**

**9.** `journalctl -u check -e`。
进阶（实战最有效的一招）：把 `ExecStart` 后面的命令**单独复制出来在终端跑一遍** —— systemd 不报错不代表命令没问题，单独跑能立刻暴露路径错、权限不足、脚本没执行位等问题。

**10.** 原因：只 `start` 没 `enable`，开机时没人拉它。
修：`systemctl enable check`（再 `systemctl start check` 让这次也跑起来）。
另：`WantedBy` 决定它挂在哪个 target 上，写错 target 也会导致开机不起来。

</details>

### 加分题（10 分）

**11.** 磁盘告警，`du` 发现 `/var/log/journal/` 占了 5G。怎么**安全地**清掉？怎么让它**以后不再无限涨**？（写命令）

<details>
<summary>答案与解析</summary>

**1.** 方便在：① 一个入口 `-u 服务名`，不用满地找文件；② 带元数据，能按时间/级别/开机次数**精确过滤**；③ `--since/--until` 一行搞定时间范围；④ `-b -1` 能回溯上次开机；⑤ `--vacuum-*` 自带清理；⑥ 和 `systemctl` 是一条链。
/var/log 没被淘汰：① 纯文本，grep/awk/ELK 都能吃；② 很多程序自己写文件，压根不经过 systemd（nginx 的 access.log journald 里没有）；③ 持久化稳（journald 默认存内存，重启丢）；④ 兼容老系统/容器。

**2.** 错。`journald` 是**二进制**，`cat` 出来是乱码、`grep` 也会漏匹配，只能用 `journalctl` 查。

**3.** `journalctl -u nginx`
**4.** `journalctl -u nginx -f`
**5.** `journalctl -u nginx --since "14:00" --until "15:00" -p err`
　（`-p err` 天生就是"err 及以上"，不用另外写级别范围；不带日期默认今天）
**6.** `journalctl -u nginx -b -1`

**7.** ① `secure`　② `messages`（rsyslog 是服务名，不是文件）　③ `dmesg`（或敲 `dmesg`）　④ `cron`

**8.** `/etc/logrotate.conf` + `/etc/logrotate.d/`；由 cron 每天执行 **`/etc/cron.daily/logrotate`**。
　注意：logrotate **不是服务**（`systemctl status logrotate` 会报 Unit not found），它是被叫一次干完就退出的命令。

**9.** ① `rotate 14`　② `compress`　③ `create 0640 nginx nginx`　④ `postrotate ... endscript`
　`postrotate` 里写 `nginx -s reopen` 是因为 logrotate 只改文件名，nginx 握的是 inode，得通知它重新打开。

**10.** 根因：**程序认 inode，不认文件名**。两种解法：
　① `postrotate` 里通知程序 reopen（`nginx -s reopen` / `kill -USR1`）—— 无丢失，需程序支持；
　② 配置加 `copytruncate`（复制出来再清空原文件，inode 不变）—— 程序无感知，但复制与清空之间可能丢几行。

**11.**
```bash
journalctl --disk-usage
journalctl --vacuum-size=500M        # 或 --vacuum-time=7d
# 永久：/etc/systemd/journald.conf
[Journal]
SystemMaxUse=500M
MaxRetentionSec=7day
systemctl restart systemd-journald
```
　别 `rm -rf`：正在被写入的文件被删后句柄还在，**空间不释放**（`lsof | grep deleted` 可见），且日志断档。

</details>

**10.（12 分）** 磁盘告警：`/var/log/myapp/app.log.1` 有 **8G 且还在涨**，新建的 `app.log` 一直是 **0 字节**。

### 加分题（10 分）

**11.** `journalctl --disk-usage` 显示日志占了 5G。怎么安全瘦身？怎么让它以后不再无限涨？为什么不能 `rm -rf /var/log/journal`？

<details>
<summary>答案与解析</summary>

**1.** 错在两处：① `/var/log` 下是**纯文本**可以 grep；② `/var/log/journal/` 是**二进制**，grep 不出来。
更关键的是**内容不同**：journald 只收 systemd 接管的输出，应用自己写的业务日志它根本没有。

**2.** ① 查应用自己写的业务日志（nginx access.log、MySQL 慢日志）；② 要用 grep/awk 处理或交给 ELK/filebeat 采集（必须是纯文本）；③ 机器重启过、journald 未持久化时历史已丢，只剩 /var/log。

**3.** `journalctl -u mysql -f`
**4.** `journalctl -p warning -b`（`-b` 就是本次开机，**不是 `-b 1`**）
**5.** `journalctl -u sshd --since "2026-09-17 20:00" --until "2026-09-18 08:00" -p err`
　跨天必须写全日期，否则默认是"今天"，时间区间会反。
**6.** `journalctl -u docker -b -1`（`-e` 可直接跳到末尾）

**7.** ① `cron`　② `secure`　③ `dmesg`（命令 `dmesg`）　④ `messages`　⑤ `boot.log`　⑥ `yum.log`

**8.** `/etc/logrotate.conf`　`/etc/logrotate.d/`　`/etc/cron.daily/logrotate`
　记住是 **cron.daily**（cron 的 daily 目录），不是 daily.d。

**9.** 隐患一：`create 0644 root root` —— 若 myapp 以普通用户运行，新文件属主是 root，**程序写不进去，日志断档**。
　隐患二：`*.log` 会匹配多个文件却**没写 `sharedscripts`** —— postrotate 里的脚本会被执行 **N 遍**，信号发 N 次。

**10.** 根因：**inode**。logrotate 改名不影响程序手里的句柄，它继续往 `app.log.1` 写。
　① 通知 reopen（推荐）：`kill -USR1` / `nginx -s reopen`，无丢失，但要求程序支持信号；
　② `copytruncate`：复制后清空原文件，inode 不变，程序无感知，代价是可能丢几行。

**11.** 同 A 卷第 11 题。不能 `rm -rf` 的理由：句柄还在 → 空间不释放；日志断档。

</details>
