## 案例三：端口被占用，新服务起不来（80 端口冲突）

**现象**：业务侧要在 `myLinux486` 上临时发布一个内部静态站点，监听 **80** 端口。启动脚本直接失败，报错：

```
Address already in use
```

服务进程没起来，页面访问不通。

**第一步：确认端口是不是真的被占了**

```bash
ss -tlnp | grep :80
```

输出（节选）：

```
LISTEN  0  128  *:80  *:*  users:(("nginx",pid=13142,fd=6),("nginx",pid=13143,fd=6))
```

`*:80` 表示**所有网卡都在监听 80**，占用者是 nginx，master 进程 PID **13142**。

**第二步：确认这个占用者是谁、能不能动它**

```bash
ps -ef | grep -E "nginx|13142"      # 看它是什么、跑的什么命令
systemctl status nginx              # 是不是 systemd 管的正规服务
ss -lntp                            # 顺带看整台机器的监听全貌
curl -I localhost                   # 它还在正常提供服务吗
```

这一步**不能省**。占用端口的进程可能是正在跑的正式业务，直接 kill 就是把别人的服务干掉。

**第三步：判断处理方式——不是所有占用都要 kill**

本次确认下来：这个 nginx 是**早期遗留的旧静态站点服务**，还在正常响应，只是不再承担主要流量，挂在 80 上属于历史遗留。

所以正确处理不是杀掉它，而是**把它迁到 8080，把 80 让给新业务**：

```bash
cp /etc/nginx/nginx.conf /etc/nginx/nginx.conf.bak   # ① 改之前备份

grep -rn "listen" /etc/nginx/nginx.conf /etc/nginx/conf.d/   # ② 找 listen 写在哪

# ③ 把 80 改成 8080（IPv4 和 IPv6 两行都要改）
sed -i 's/^\(\s*listen\s*\)80;/\18080;/' /etc/nginx/nginx.conf
sed -i 's/^\(\s*listen\s*\)\[::\]:80;/\1[::]:8080;/' /etc/nginx/nginx.conf

nginx -t                            # ④ 语法检查，必须 successful
systemctl restart nginx             # ⑤ 换端口建议 restart
systemctl status nginx              # ⑥ 确认 active (running)
```

**第四步：验证端口真的让出来了**

```bash
ss -lntp | grep -E ':80|:8080'      # nginx 应该在 8080，80 上没有 LISTEN 了
curl -I localhost:8080              # 旧站点迁过去之后仍然可访问
```

确认 80 空出来后，新服务正常启动，`curl -I localhost` 返回 200。

**根因**：80 端口被早期遗留的 nginx 静态站点占用，且监听的是 `*:80`（全网卡），新业务同样要用 80 时发生**端口冲突**。不是进程异常，是**端口规划冲突**。

**解决**：把遗留 nginx 迁移到 8080 并保留其服务，释放 80 给新业务，双方共存。

---

**端口占用的完整排查命令链（背这个）**

```bash
ss -tlnp | grep :80        # ① 谁在监听这个端口？-p 直接给出 PID（最关键的参数）
ps -ef | grep <PID>        # ② 这个进程是干什么的
systemctl status <服务名>   # ③ 是不是正规服务，谁在管它
kill <PID>                 # ④ 确认该停之后：先温柔地请它走
kill -9 <PID>              #    杀不掉才用 -9（强杀，不给收尾机会，可能丢数据）
ss -tlnp | grep :80        # ⑤ 验证端口已释放
```

**换个端口 vs 干掉占用者——怎么选**

| 情况 | 处理 |
|---|---|
| 占用者是**正常业务**，还在提供服务 | 改自己（或改它）的端口，别 kill |
| 占用者是**上次没关干净的残留进程** | 确认无流量后 `kill` |
| 占用者是**僵尸/卡死**的进程 | `kill` 不行再 `kill -9` |
| 谁都确认不了 | 先查日志 `journalctl -u 服务名`，别猜 |

---

**学到什么**

1. **`ss -lntp` 里 `-p` 是最关键的参数**——没有 `-p` 你只能看到"80 被占了"，有了 `-p` 才能直接看到是哪个进程、PID 多少。`-l` 只看监听、`-n` 不解析服务名（更快）、`-t` 只看 TCP；
2. **端口被占 ≠ 杀掉占用者**。这是本次最大的收获：占用 80 的 nginx 是正常业务，杀了就是事故。正确做法是**先判断它该不该停**，改端口往往比 kill 更安全；
3. **kill 之前必须确认三件事**：这个进程是干什么的、有没有业务在用、是不是自己会话的依赖（之前误杀 sshd 就是没确认）；
4. **`kill` 优先于 `kill -9`**。`-9` 是 SIGKILL，进程收不到信号、来不及保存数据就被干掉，只在 `kill` 无效时使用；
5. **别把 `TIME_WAIT` 当成占用**。真正阻止你绑定端口的是 `LISTEN` 状态；`ss -antp | grep :80` 里一堆 `TIME_WAIT` 是正常挥手残留，过一会儿自己就没了，不用管；
6. **监听地址要看清楚**：`*:80` 是全网卡监听，`127.0.0.1:80` 是只听本机（外部访问不到）。排查"服务起了但外面连不上"时，第一眼就该看这一列；
7. **`ss` 取代 `netstat`**。`netstat` 来自 net-tools 包，新系统默认不装，且在大连接数机器上慢。`ss` 直接读内核，快得多；
8. **改服务端口还要顺带考虑防火墙和 SELinux**：`firewall-cmd --add-port=8080/tcp --permanent && firewall-cmd --reload`；SELinux 下非标端口可能还要 `semanage port -a -t http_port_t -p tcp 8080`；
9. **`systemctl restart` 和 `reload` 的区别在换端口时尤其明显**——reload 有时不重新绑定端口，换监听端口用 `restart` 更稳妥（案例二里讲过：改配置用 reload，换端口用 restart）。

**后续预防**

- 上线前先确认端口规划，避免两个服务抢同一个端口；
- 服务端口写进文档/port 登记表，别靠人记；
- 关键服务统一交给 systemd 托管，端口冲突时能通过 `systemctl status` 快速确认归属；
- 监听端口纳入监控（第 5 周 Prometheus 会覆盖），端口掉了立刻告警。
