# 学习总结 —— 磁盘管理

> 标准：**能说出磁盘满了的完整排查步骤**



## 知识点整理

###  df vs du —— 「看账本」与「数实物」

**本质区别：**

| | df | du |
|---|---|---|
| 数据来源 | 读文件系统元数据（超级块里的记账） | 老老实实遍历目录树，逐级加总 |
| 视角 | 整个分区 / 挂载点 | 指定目录及其子目录 |
| 速度 | 快（不读文件内容） | 慢（要走遍每个文件） |

**面试一句话：「df 看账本，du 数实物。」**

**场景题标准答法**（df 高 + du 低）：

1. 第一反应：**有进程攥着已删除的文件不放**，删了 inode 但数据块没释放 → `lsof | grep deleted` 定位进程，`echo > 文件名` 截断或 kill 进程；
2. 第二反应：`df -i` 看 inode 是不是另一种"满"（见 2.5）；
3. 别忽略：df 的统计里含文件系统保留块和 inode 表，与 du 的"文件可见大小"本来就不是一套账。

### LVM 三层结构

- **PV（Physical Volume，物理卷）**：物理层面的磁盘或分区，LVM 的原材料；
- **VG（Volume Group，卷组）**：把多个 PV 打包成一个大资源池；
- **LV（Logical Volume，逻辑卷）**：从 VG 里切出来的一块，最终拿来用的"分区"。

**完整链路五步**（别说漏第三步）：

```
PV（物理盘/分区） → VG（资源池） → LV（逻辑卷） → mkfs 格式化 → mount 挂载
```

**可复用的比喻**（面试就这么讲）：PV 是一个个没打通的水坑，VG 是把水坑打通装修成的大水池，LV 是把水池分成快速区/成人区/儿童区，实现分流管理。

**拓展（面试加分项）：**

- LV 扩容不用卸载：`lvextend -L +10G /dev/vg0/lv0` 然后 `resize2fs`（ext4）或 `xfs_growfs`（xfs）在线扩文件系统；
- LVM 支持快照，升级/备份前先打快照，出事秒回滚；
- 常用查看命令：`pvs` / `vgs` / `lvs` / `lvdisplay`。

###  mount

- **本质**：把块设备「钉」到某个**目录**（挂载点）上，之后访问这个目录就等于访问那块盘；
- 不 mount，系统知道有这块硬件，但不知道从哪条路进它的文件系统；
- **/etc/fstab**：开机自动挂载的配置表，改完用 `mount -a` 验证，写错重启可能起不来（先 `mount -a` 测再重启是保命习惯）；
- **卸载报 `target is busy`**：`lsof +f -- /挂载点` 或 `fuser -mv /挂载点` 查谁在占用，先退进程；
- 安全挂载选项：`ro`（只读）、`noexec`、`nosuid`，`nodev`。

### 2.4 磁盘满排查完整流程（验收大题标准答法）

```
1. df -h                 → 看哪个分区/挂载点爆了（看空间）
   df -i                 → 同一台机器必须一起看（看 inode，双保险）
2. 进入该挂载点，du -xh --max-depth=1 . | sort -rh | head
                        → 快速锁定大头目录（-x 不跨文件系统，--max-depth=1 只看一层）
3. 逐层下钻：du -xh --max-depth=1 目录 | sort -rh | head
                        → 直到定位到具体文件/目录
4. 按性质处理：
   - 日志文件 → echo > 文件  截断（别 rm，rm 可能句柄不放）
   - 整个目录不要 → 确认无进程占用后删
   - 文件名删了空间没放 → lsof | grep deleted → kill 进程或截断
5. 海量小文件场景 → df -i 确认是 inode 满 → 清理 + 查是谁在狂建文件
6. 兜底：systemctl restart 服务（重启是最后手段，不是常规手段）
```

**三类"磁盘满"故障要能互相区分：**

| 现象 | 病根 | 确诊命令 |
|---|---|---|
| 空间满 | 真有东西占着 | `df -h` |
| inode 满 | 海量小文件 | `df -i`（IUse% 100%） |
| 幽灵占用 | 进程攥着已删文件 | `df -h` 与 `du` 对不上 + `lsof \| grep deleted` |

**优先看的目录**：`/var/log`（日志，生产环境十有八九）、`/tmp`、`/var/tmp`、家目录里的 core dump。

### inode 与磁盘占比是两块独立的表（追加问答）

- **空间占比和 inode 占比互不影响**：`df -h` 可能只显示 30%，`df -i` 照样 100%；
- 原因：**一个文件再小也占一个 inode**，inode 记录的是"文件名、权限、位置"等元数据，与文件内容大小无关；
- 典型现场：`No space left on device` 但空间明明富裕——就是 inode 打满；
- 惯犯场景：session 文件、缓存文件、邮件队列、程序疯狂吐日志切片等**海量小文件**；
- 排查：`df -i` 看哪个分区 IUse% 满 → `find /路径 -size 0 | wc -l` 或 `find /路径 -type f | wc -l` 数文件量 → 定位制造者；
- 解决：清理小文件治标；长期方案是备份数据后 `mkfs` 重新规划 inode 数量（`-N` 参数）；
- 注意：inode 表本身占磁盘空间，但那是 `mkfs` 时一次性划走的，不随文件数量增长，别和 inode 占用率混淆。

## 三、错误点清单 

| # | 原来的说法 | 正确表述 |
|---|---|---|
| 1 | df/du「先入为主的关系」 | 「df 看账本（元数据），du 数实物（遍历目录）」 |
| 2 | `losf` | `lsof`（list open files） |
| 3 | 「挂载在**文件**上」 | 挂载点是**目录**，mount 把设备钉到目录上 |
| 4 | 「LV 就是挂载的分区」 | LV 是逻辑卷，中间还有 **mkfs 格式化**这一步才 mount |
| 5 | `du -sh /` 全盘扫 | `du -xh --max-depth=1` 逐层下钻，`-x` 不跨文件系统 |
| 6 | 只跑 `df -h` | **`df -h` 和 `df -i` 必须一起看** |
| 7 | 「再不行就重启大法」 | 重启排最后；优先 `echo > 文件` 截断 / kill 进程 |
| 8 | 排查路径没提 `/var/log` | 生产环境磁盘满，先看 `/var/log` |

## 四、自测 

1. **df 和 du 哪个更准？** —— 看目的：看分区余量用 df，看哪个目录吃了空间用 du；两者对不上本身就是线索。
2. **LVM 怎么在线扩容？** —— lvextend 扩 LV → resize2fs / xfs_growfs 扩文件系统，不用卸载。
3. **文件删了空间不释放，怎么办？** —— lsof | grep deleted 找进程，截断或 kill，别干等。
4. **没有小文件也可能 inode 满吗？** —— 会，任何"文件数量远超预期"的场景都算，不挑大小。
5. **fstab 写错了会怎样？** —— 重启可能进不了系统；先用 `mount -a` 验证再重启。
6. **umount 卸不掉提示 busy？** —— lsof / fuser 查占用进程，先退出再卸。
