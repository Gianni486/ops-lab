## 一、两套日志体系并存

CentOS 7 里日志是**两套并行**的，别以为有了 journalctl 就不需要 /var/log。

| 对比项 | journald（用 `journalctl` 查） | 传统 syslog（`/var/log/` 下的文件） |
|--------|------------------------------|-----------------------------------|
| 存哪 | `/run/log/journal`（内存，重启丢）<br>持久需 `/var/log/journal` | `/var/log/*` 各文件，持久 |
| 格式 | **二进制**，不能直接 cat/grep | **纯文本**，随手 cat/grep/awk |
| 谁来写 | systemd 统一接管：服务的 stdout、stderr、syslog 全收 | 各应用自己写文件 |
| 查询方式 | `journalctl` 一条命令多维过滤 | 每个文件单独翻 |
| 代表服务 | systemd 管理的那些服务 | nginx、mysql、Java 应用等自己写日志的程序 |

**journalctl 方便在哪（记住这 4 条就够用）**

1. **集中**：所有服务日志一处汇总，不用去 /var/log 挨个找文件。
2. **多维过滤**：按服务 `-u`、按时间 `--since/--until`、按级别 `-p`、按开机次数 `-b`。
3. **和 systemctl 打通**：服务挂了，`journalctl -u 服务名` 直接看到它的遗言。
4. **自带清理能力**：`--vacuum-size` / `--vacuum-time` 一条命令瘦身。

**/var/log 为什么还没被淘汰**

1. **纯文本**，任何工具都能处理（`grep` / `awk` / `sed` / 日志采集工具）。
2. **兼容性**，几十年来的脚本和运维习惯都建在这上面。
3. **很多应用自己写日志**，压根不经过 systemd，journald 管不着（比如 nginx 的 access.log）。
4. **持久化兜底**：journald 在 CentOS 7 默认存内存里，重启就丢；/var/log 是可靠的长期记录。

> ⚠️ `/var/log/journal/` 下的文件是**二进制**的，`cat` 出来是乱码、`grep` 也可能漏匹配，**必须用 journalctl 查**。

## 二、journalctl 命令速查

```bash
# 基本
journalctl                          # 看全部（旧的在前，按空格翻页，q 退出）
journalctl -e                       # 直接跳到末尾
journalctl -n 50                    # 只看最后 50 行

# 按服务（最常用）
journalctl -u nginx
journalctl -u nginx -e              # 看末尾（配合 status 排错）

# 实时跟随（tail -f 效果）
journalctl -u nginx -f

# 按时间
journalctl --since today
journalctl --since "2026-09-17 14:00" --until "2026-09-17 15:00"
journalctl --since "1 hour ago"
journalctl --since yesterday

# 按级别（从高到低：emerg 0 alert 1 crit 2 err 3 warning 4 notice 5 info 6 debug 7）
journalctl -p err                   # 错误及以上
journalctl -p err -b                # 本次开机以来的错误

# 按开机次数
journalctl -b                       # 本次启动之后
journalctl -b -1                    # 上一次开机（机器重启过就用它）
journalctl -b -2                    # 上上次

# 内核日志
journalctl -k                       # 等价于 dmesg

# 组合拳（面试/实战高频）
journalctl -u nginx --since "14:00" --until "15:00" -p err
journalctl -u nginx -b -1           # 上次开机时 nginx 为什么挂了

# 占空间与清理
journalctl --disk-usage             # 看日志占了多少
journalctl --vacuum-size=500M       # 缩到 500M 以内
journalctl --vacuum-time=7d         # 只保留最近 7 天
```

## 三、/var/log 关键文件对照表

CentOS 7 / RHEL 系：

| 文件 | 里面是什么 | 什么时候翻它 |
|------|-----------|-------------|
| `/var/log/messages` | 系统主日志（杂事全在这） | 出问题没头绪时的第一站 |
| `/var/log/secure` | 认证、登录、sudo | **SSH 被暴力破解**、登录失败、提权 |
| `/var/log/dmesg` | 内核启动信息 | 硬件、驱动问题（或直接敲 `dmesg`） |
| `/var/log/cron` | 定时任务执行记录 | "计划任务到底跑没跑" |
| `/var/log/boot.log` | 开机启动过程 | 系统启动慢 / 服务起不来 |
| `/var/log/yum.log` | yum 安装卸载记录 | 谁什么时候装了什么包 |
| `/var/log/maillog` | 邮件相关 | 邮件服务排错 |
| `/var/log/audit/audit.log` | SELinux / 审计 | 权限被拒绝又找不到原因时 |

> Ubuntu / Debian 系略有不同：主日志是 `/var/log/syslog`，认证日志是 `/var/log/auth.log`。

## 四、日志轮转 logrotate

**为什么要轮转**：日志一直写、从来不删，总有一天撑爆磁盘 —— 这就是周六实验"故障一：磁盘写满"的真实成因。

### 谁在管

- 全局配置：`/etc/logrotate.conf`
- 各应用配置：`/etc/logrotate.d/` 目录下一个服务一个文件
- 每天由 **cron** 定时调用：`/etc/cron.daily/logrotate`

### 一份典型配置

```conf
/var/log/nginx/*.log {
    daily              # 每天轮转（也可 weekly / monthly / size 100M）
    rotate 14          # 保留 14 份历史，超了最老的被删
    compress           # 压缩旧日志（xxx.log.2.gz）
    delaycompress      # 延后一轮再压（配合 reopen，避免程序还在写就被压）
    missingok          # 日志文件不存在也不报错
    notifempty         # 空文件不轮转
    create 0640 nginx nginx   # 轮转后创建新文件，指定权限和属主
    sharedscripts      # 多个日志只执行一次脚本
    postrotate
        nginx -s reopen      # 通知 nginx 重新打开日志文件
    endscript
}
```

### 常用命令

```bash
logrotate -d /etc/logrotate.conf        # 演练（dry run），只打印不真做
logrotate -f /etc/logrotate.d/nginx     # 强制执行一次
cat /var/lib/logrotate.status           # 看每个日志上次轮转的时间
```

### ⚠️ 最容易踩的坑：轮转了但程序还在写旧文件

**现象**：`xxx.log.1` 每天都在变大，新建的 `xxx.log` 一直是 0 字节。

**根因**：程序（nginx 等）打开文件后，认的是 **inode**，不是文件名。logrotate 只是把文件**改了名**，程序手里的句柄还指向那个 inode，所以照样往改名后的 `xxx.log.1` 里写。

**两种解法**：

| 解法 | 做法 | 特点 |
|------|------|------|
| **通知重开**（推荐） | `postrotate` 里加 `nginx -s reopen`，或用 `kill -USR1 $(cat /run/nginx.pid)` | 无日志丢失，需要程序支持 reopen 信号 |
| **copytruncate** | 配置里加一行 `copytruncate`：先把内容复制成备份，再把原文件**清空**（inode 不变） | 程序无感知；但复制和清空之间有一瞬间隙，可能丢几行 |

## 五、journal 日志撑爆磁盘怎么办

```bash
# 1. 先看占了多少
journalctl --disk-usage

# 2. 安全瘦身（不是 rm -rf！）
journalctl --vacuum-size=500M      # 压到 500M 以内
journalctl --vacuum-time=7d        # 只留最近 7 天

# 3. 永久限制：编辑 /etc/systemd/journald.conf
[Journal]
SystemMaxUse=500M                  # 最大占用
MaxRetentionSec=7day               # 最多保留 7 天

systemctl restart systemd-journald
```

> 别用 `rm -rf /var/log/journal` —— 正在写的句柄被删会导致空间不释放、日志彻底断档。用 vacuum，它是干净地"登记删除"。

## 六、易错点清单

| # | 易错点 | 正确认知 |
|---|--------|---------|
| 1 | 以为 journal 日志能 cat / grep | 是**二进制**，只能 `journalctl` 查 |
| 2 | 不知道 `-f` | `-f` = 实时跟随，就是 `tail -f` 的替代品 |
| 3 | 不知道 `-p err` | 按优先级过滤，`-p err` 只看错误及以上 |
| 4 | 不知道 `-b -1` | 看**上一次开机**的日志，机器重启过后查故障就用它 |
| 5 | 把 CentOS 主日志记成 rsyslog | 主日志是 `/var/log/messages`（`rsyslog` 是服务名） |
| 6 | 不知道内核日志看哪 | `/var/log/dmesg` 或直接敲 `dmesg`、`journalctl -k` |
| 7 | logrotate 的位置 | `/etc/logrotate.conf` + `/etc/logrotate.d/`，由 `/etc/cron.daily/logrotate` 每天跑 |
| 8 | 不知道轮转后要 reopen | 改文件名不影响 inode，必须通知程序重开或加 `copytruncate` |
| 9 | 日志满了直接 rm | 用 `journalctl --vacuum-size` / `--vacuum-time` |
| 10 | **看了视频没敲命令** | 命令类的东西，不敲等于没学 —— 本笔记所有代码块都去虚拟机上跑一遍 |
